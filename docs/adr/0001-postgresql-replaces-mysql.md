# PostgreSQL replaces MySQL (single DB, not DB-agnostic)

The inherited template was MySQL-backed. We convert it to be **PostgreSQL-only** — removing the MySQL driver, `flyway-mysql`, and all MySQL config rather than making the template support both engines via configuration. Single-DB keeps the migration and test surface honest and unambiguous (a "DB-agnostic" template doubles the migration/test matrix forever and one path silently rots). The repo name (`oauth-postgresql`) and the stated mission ("just a conversion") both point here. Consequence: enum columns become `VARCHAR` (entities use `@Enumerated(EnumType.STRING)`), and `V1__init_schema.sql` is rewritten as Postgres DDL validated against the JPA entities under `ddl-auto: validate`. If a future project needs MySQL, it branches from upstream rather than this template carrying both.

## Revision: scope includes correctness fixes, not only a faithful port

ADR-0001 originally framed the work as a minimal/faithful port. The operator's "all tests must actually work" directive widened the scope to include correctness fixes surfaced during the conversion, specifically: (1) adding `maven-failsafe-plugin` so the six `*IT` classes actually run (they never had before — a silent gap, not a regression); (2) fixing the `audit_events.type` enum drift — the old MySQL `V1` listed 8 values while the `AuditEventType` Java enum has 18, which fails `ddl-auto: validate` against a real DB; (3) pointing `RoleProtectionPremiumIT` at the reachable `/api/premium/content` endpoint instead of the misconfigured `/api/admin/premium/content` copy (the latter sits under an `/api/admin/** → hasRole('ADMIN')` filter rule that contradicts its `@PreAuthorize("hasRole('PREMIUM')")`, making it unreachable by a pure PREMIUM user); (4) deleting dead test scaffolding and a duplicate `application-test.yaml`. These go beyond a byte-for-byte port but are required for a green, trustworthy suite on PostgreSQL.
